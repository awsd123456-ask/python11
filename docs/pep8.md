# PEP8 Python编码规范

PEP8 是 Python 官方的代码风格指南，帮助开发者写出更规范、更易读的代码。

## 一、代码编排

### 1. 缩进
- 使用 4个空格缩进
- 不使用Tab，更不能混合使用Tab和空格

### 2. 每行最大长度
- 每行最多79个字符
- 换行可以使用反斜杠，最好使用圆括号
- 换行点要在操作符的后边敲回车

### 3. 空行规则
- 类和top-level函数定义之间空两行
- 类中的方法定义之间空一行
- 函数内逻辑无关段落之间空一行
- 其他地方尽量不要再空行

## 二、文档编排

### 1. 模块内容顺序
模块说明和docstring → import → globals&constants → 其他定义

import部分顺序：标准库 → 三方库 → 自己编写的模块（之间空一行）

### 2. import规则
- 不要在一句import中导入多个库
- 如果采用from XX import XX引用库，可以省略'module.'，但可能出现命名冲突

## 三、空格的使用

总体原则：避免不必要的空格

1. 各种右括号前不要加空格
2. 逗号、冒号、分号前不要加空格
3. 函数的左括号前不要加空格
4. 序列的左括号前不要加空格
5. 操作符左右各加一个空格
6. 函数默认参数使用的赋值符左右省略空格
7. 不要将多句语句写在同一行
8. if/for/while语句中，即使执行语句只有一句，也必须另起一行

## 四、注释

总体原则：错误的注释不如没有注释。当代码发生变化时，第一件事就是要修改注释！

### 1. 块注释
在一段代码前增加的注释，在'#'后加一空格

### 2. 行注释
在一句代码后加注释，尽量少使用

### 3. 避免无谓的注释

## 五、文档描述

1. 为所有的公有模块、函数、类、方法写docstrings
2. 非公有的没有必要，但是可以写注释

## 六、命名规范

1. 尽量避免单独使用小写字母'l'，大写字母'O'等容易混淆的字母
2. 模块命名尽量短小，使用全部小写的方式，可以使用下划线
3. 包命名尽量短小，使用全部小写的方式，不可以使用下划线
4. 类的命名使用CapWords的方式
5. 异常命名使用CapWords+Error后缀的方式
6. 函数命名使用全部小写，可以使用下划线
7. 常量命名使用全部大写，可以使用下划线
